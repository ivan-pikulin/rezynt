# Writing Guide

Правила записи Memory Bank для этого репозитория.

## Язык и стиль

- Пиши по-русски.
- Имена файлов, путей, переменных, маршрутов и команд оставляй на английском.
- Пиши коротко: только то, что помогает быстро ориентироваться в коде.
- Не переписывай код и не вставляй длинные примеры, если достаточно ссылки на исходный файл.

## Структура

- Один домен = один файл или одна папка.
- Один файл = одна тема.
- Сначала карта и правила, потом детали.
- Если тема начинает разрастаться, выноси её в отдельный файл вместо длинного монолита.

## Источники истины

- Код репозитория.
- Текущие `spec.xml`.
- `AGENTS.md` и `CLAUDE.md` для рабочих правил.
- Фактическая структура каталогов, а не старые предположения из документации.

## Что не хранить

- Дублирование кода.
- App-specific планы и черновики, если они не нужны для текущей навигации.
- Устаревшие пути, фичи и архитектурные решения без пометки legacy.

## Обновление

- Каждый файл Memory Bank заканчивается датой последнего обновления.
- Если меняешь код в зоне ответственности файла, обнови и этот файл.
- Если выяснилось, что документ устарел, не прячь это: пометь его как legacy или перепиши под текущий код.
